# 达人合作自动化流程规格

## 目标

这个 skill 用于启动和运营独立的达人合作项目。它创建项目级飞书多维表格，把名单、沟通、内容和财务放在同一数据主档；自动处理明确、低风险的标准动作，并在价格、合同、账户额度、内容判断和付款等关键节点交由项目负责人确认。

每个项目独立运行。不要把一个项目的达人、邮件线程、预算或付款记录混入另一个项目。

## 项目初始化

每次新项目启动时，创建一份独立飞书多维表格，作为唯一数据主档。初始化脚本先以 dry-run 展示字段计划，确认后才用 `--apply` 创建新 Base；创建结果写入 manifest。脚本不修改旧 Base、不发送外部邮件，也不默认配置视图。

名单导入使用当前项目 manifest，先规范化并按“平台 + 主页链接”去重，再在 dry-run 报告候选和跳过项；确认后以不超过 500 条一批写入达人主档。`@用户名` 会按平台补全主页域名。没有主页链接或昵称的行不写入；同一项目中已有的身份键不重复写入。

每次新项目启动时，创建一份独立飞书多维表格，作为唯一数据主档。创建时收集下列配置：

- 项目名称、负责人、时区
- 品牌/产品名、项目简介、Brief 附件
- 触达模板、询价模板、议价模板、合作确认模板、注册说明模板、脚本推进模板、内容反馈模板、收款资料模板
- 是否附合同；若附，上传本项目合同模板
- 项目投放窗口，可留空
- 默认平台、目标达人标签、预算与币种
- 开票主体与注册地址：从项目私有配置读取，不写入公开版默认值

## 数据主档

初始化脚本当前先创建可稳定写入的基础字段，并将跨表身份保存为 `平台 + 主页链接`。这比未经验证就创建关联字段更可恢复：字段名会变，但项目 manifest 会保存 app/table ID，记录写入可以用一致的身份键。关联字段、成员字段和视图筛选属于后续 API 验证项，不能在初始化成功的表上默认宣称已配置。

### 1. 达人主档

一位达人一行。以“平台 + 主页链接”为唯一去重键，不以昵称或邮箱单独去重。

| 字段 | 类型/说明 |
|---|---|
| 达人昵称 | 文本，主展示字段 |
| 平台 | 单选：TikTok、Instagram、YouTube、X、其他 |
| 主页链接 | URL，与平台共同去重 |
| 粉丝数量 | 数字，保留原始数值 |
| 联系方式 | 多选：Gmail、TikTok DM、Instagram DM、经纪人、其他 |
| 联系邮箱 | 邮箱 |
| Gmail线程 ID | 当前合作线程，唯一匹配后回填 |
| 最近邮件 Message ID | 最近一次已处理邮件 |
| 来源 | 文本或单选，记录批次/搜索来源 |
| 达人标签 | 多选，例如 AI、学习、效率、职场 |
| CPM | 数字；有可比播放数据时计算 |
| 首次报价 | 金额 |
| 币种 | 单选 |
| 第一轮议价目标/结果 | 金额 |
| 第二轮议价目标/结果 | 金额 |
| 最终合作价格 | 金额，确认后锁定 |
| 合作内容 | 长文本：平台、交付物、时长、授权等 |
| 最新状态 | 单选，见“状态机” |
| 具体进度 | 长文本，仅保留当前一句话摘要 |
| 首次触达时间 | 日期时间 |
| 最近互动时间 | 从沟通记录汇总 |
| 内容交付 | 关联内容交付表；初始化第一版使用 `关联交付物名称`，待关联字段 API 验证后再升级 |
| 财务记录 | 关联财务表；初始化第一版使用 `关联达人主页键`，待关联字段 API 验证后再升级 |
| 负责人 | 成员 |
| 风险/备注 | 长文本 |

### 2. 沟通记录

`关联达人` 的初始化字段名为 `关联达人主页键`，先用 `平台 + 主页链接` 作为稳定身份键；关联字段待 API 验证后再升级。

每封邮件或每条私信一行，是沟通的审计记录。外发 Gmail 必须在既有 threadId 中回复，并显式写入收件人邮箱；不要依赖邮件客户端自动推断收件人。

| 字段 | 类型/说明 |
|---|---|
| 关联达人 | 关联达人主档，必填 |
| 沟通时间 | 日期时间 |
| 渠道 | 单选：Gmail、TikTok DM、Instagram DM、经纪人、其他 |
| 方向 | 单选：收到、发出 |
| 沟通类型 | 单选：首轮邀约、询价、议价 1/2、合作确认、注册、充值后推进、脚本反馈、视频反馈、发布、付款资料、其他 |
| 邮件线程 ID | Gmail 必填 |
| 邮件 Message ID | 文本 |
| 收件人邮箱 | 邮箱，外发 Gmail 必填并与主档校验 |
| 邮件主题 | 文本 |
| 内容摘要 | 长文本 |
| 完整正文/DM 文案 | 长文本或邮件链接 |
| 附件/模板版本 | 附件或关联 |
| 发送审批状态 | 单选：待确认、已确认、已发送、发送失败、不发送 |
| 解析结果 | 单选：已报价、未报价有意向、拒绝、已注册、已交稿、自动回复、待人工判断 |
| 提取报价/币种 | 金额与单选 |
| 下次跟进时间 | 日期时间 |
| 执行异常 | 长文本 |

### 3. 内容交付

一个达人每个交付物一行。跨多个平台发布同一条内容时，不拆为多条交付物；在同一行标记全部交付平台，并记录每个平台链接。

| 阶段 | 字段 |
|---|---|
| 基础 | 关联达人、交付物名称、内容形式、主发布平台、交付平台、跨发、内容状态、内容负责人 |
| 脚本 | 脚本链接/附件、收到时间、审核截止时间、审核意见、审核结论、脚本修改轮次、剩余免费修改次数、脚本终版、通过时间 |
| 视频 | 一稿/二稿/终稿链接或附件及各自收到时间、审核意见、审核结论；视频修改轮次、剩余免费修改次数、终稿通过时间 |
| 文案 | 发布文案、审核意见、审核结论、通过时间 |
| 发布 | 计划发布时间（可空）、实际发布时间、各平台发布链接、已发布平台、发布完成度、发布证据 |
| 协作 | 审核记录（按时间追加，不覆盖历史）、最新审核摘要、异常/备注 |

规则：

- 所有达人先完成脚本审核，才可进入视频一稿。
- 脚本通过后，一稿默认 3 至 5 天内交付。外发时给具体日期，默认以通过日加 5 个自然日计算。
- 脚本、视频和文案收到后，48 小时内应完成审核反馈。
- 脚本默认两轮免费修改，视频默认两轮免费修改，分别计数。
- 终稿和文案通过后不设默认发布日期；项目投放窗口只作提醒。

### 4. 财务

`关联达人` 的初始化字段名为 `关联达人主页键`，`关联交付物` 的初始化字段名为 `关联交付物名称`；关联字段待 API 验证后再升级。

充值与付款放在财务表。达人主档仅汇总状态，不存储财务敏感数据细节。

| 字段 | 类型/说明 |
|---|---|
| 关联达人 | 关联达人主档，必填 |
| 关联交付物 | 关联内容交付 |
| 财务类型 | 单选：充值、创作者服务费、其他 |
| 财务状态 | 单选：待注册信息、待充值、已充值、待发布完成、待收款资料与 Invoice、Invoice 审核中、付款申请待确认、付款审核中、待付款、已付款、异常 |
| 注册邮箱 | 邮箱 |
| 充值额度/单位 | 数字与单选 |
| 充值完成时间/凭据 | 日期时间与附件/URL |
| 应付金额/币种 | 金额与单选，应与最终合作价格一致 |
| 收款人法定名称 | 文本 |
| 收款方式 | 单选：PayPal、银行转账、Wise、其他 |
| 收款账户 | 长文本，限制权限 |
| Invoice 编号/文件 | 文本与附件 |
| Invoice 核验结果 | 单选：待核验、通过、金额不符、信息不全、重复 |
| 内部付款申请沟通记录 | 关联沟通记录 |
| 付款申请发送时间 | 日期时间 |
| 实际付款时间/凭证 | 日期时间与附件/URL |
| 财务负责人/异常说明 | 成员与长文本 |

## 状态机

达人主档使用以下主状态：

```text
待导入 → 待审核 → 待触达 → 已触达 → 已回复待归类
→ 待询价 / 已报价待评估 → 议价中 → 合作待确认
→ 待达人确认合作 → 待注册 → 待充值 → 合作执行中
→ 待发布完成 → 待收款资料与 Invoice → 付款申请待确认
→ 付款审核中 → 待付款 → 已付款 → 已完成
```

拒绝、报价过高、账号异常、失联、终止合作使用独立终态；不要伪装成“已完成”。

## 自动与人工闸门

| 动作 | 执行方式 |
|---|---|
| 导入名单、字段解析、去重、识别 Gmail/DM、生成首轮邮件队列 | 自动 |
| 首批 Gmail 邀约 | 项目负责人确认整批后发送 |
| DM 触达 | 人工发送；skill 仅生成文案、记录和提醒 |
| 每日 10:30 扫描活跃项目 Gmail 新邮件 | 自动，只处理上次成功扫描后的新增邮件 |
| 明确有合作意向但未报价的标准询价邮件 | 生成原 Gmail 线程完整草稿；项目负责人确认后发送 |
| 第一/第二轮议价邮件 | 项目负责人逐位确认金额后发送 |
| 合作确认、合同、下载注册说明 | 项目负责人确认后发送 |
| 充值 | 人工操作；回填完成后才可推进 |
| 充值后索要脚本提交时间邮件 | 生成原线程完整草稿；项目负责人确认后发送 |
| 脚本、视频与文案反馈 | 项目负责人填写并确认后发送 |
| 索要收款方式、账户和 Invoice | 生成完整草稿，项目负责人确认后发送 |
| 内部付款申请 | 按项目配置生成草稿，项目负责人确认后发送；公开版不提供默认 CC |
| 实际付款 | 人工完成并上传凭证 |

## Gmail 规则

- 每个达人邮件线程在主档保留 threadId 和最近 Message ID。
- 回复时显式设置 `To` 为主档中的达人邮箱，发送前比对名字、邮箱、threadId、主题、附件和项目状态。
- 线程无法唯一确定、邮件地址不一致、附件缺失、或已有同类未回复邮件时，停止外发并标记人工处理。
- 对自动回复、退信、陌生联系人、经纪人代回或解析不完整的报价，不生成可发送的询价草稿。

## DM 规则

DM 是人工动作。skill 可提供个性化文案、记录发送状态和跟进提醒，但不自动切换账号、自动重试或发起申诉，避免平台风控和账号混乱。

## 付款前置条件

只有同时满足以下条件，才可进入“待收款资料与 Invoice”：

```text
全部约定平台均已发布
+ 每个平台均有有效发布链接
+ 该交付物状态为已发布
```

向达人索要付款资料时，用一封邮件同时索要收款方式、收款账户和 Invoice，并附项目私有配置中的开票主体与地址。公开版不提供任何公司默认信息。Invoice 到达后核对抬头、地址、编号、金额、币种、收款信息和附件可读性。付款申请已发送不等于已付款；实际付款凭证回填后才可标记已付款。

## 异常处理

- 重复达人：不写入，显示去重依据。
- 无邮箱：归入 DM 待办，不生成 Gmail 记录。
- 账号/邮箱无效：标记异常，不自动重试。
- 未通过脚本审核即交视频：标记流程异常，生成补脚本草稿。
- 修改次数超限：停止自动推进，交由负责人决定继续、加价或终止。
- 跨发缺少任一平台链接：保持待发布完成，不进入付款。
- Invoice 信息不一致或重复：保持 Invoice 审核中，生成澄清草稿，不申请付款。
